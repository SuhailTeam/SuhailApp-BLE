## Method

Five participants completed a moderated, blindfolded session exercising all eight
voice commands on the Mentra Live glasses with the Suhail companion app. For each
command the moderator set the active task and the participant issued the command by
voice; the app's built-in instrumentation auto-recorded every turn (no stopwatch):
wake→first-spoken-word, end-of-speech→first-spoken-word, and full turn time. After
the session each participant completed the standard 10-item System Usability Scale
(SUS). Task success and error recoveries were derived from the app's command-routing
log (a task counts as a recovery for each repeat beyond the first).

## Results

Across the five sessions (48 recorded command turns, 38 task attempts):

| Measure | Result |
|---|---|
| Task success rate (derived) | **84%** |
| Responsiveness — end-of-speech → first spoken word (median) | **5.26 s** (n=48) |
| Wake → first spoken word (median, IQR) | 12.14 s (10.30–13.79) |
| Full turn (median) | 17.09 s |
| Recoveries per task (mean) | 0.25 |
| **SUS (mean)** | **74.5** (range 67.5–82.5) |

The mean SUS of **74.5** sits above the established ~68 average, placing the system
in the "good"/acceptable band. **Responsiveness was highly consistent** — the
end-of-speech→first-word median stayed between 5.3 and 5.8 s across every subset of
participants, giving a stable ~5 s figure for the time between a user finishing their
command and the glasses beginning to respond.

Six of the eight commands routed correctly on **100%** of attempts. Two did not:
**visual-question-answering succeeded only 20%** of the time — utterances such as
"what's on my table/desk/fridge?" were consistently mis-routed to scene description —
and **colour detection succeeded 60%** of the time (the explicit keyword "colour"
worked, but indirect phrasings did not). This is a reproducible routing weakness, not
random error, and is the clearest target for future tuning.

## Limitations

- **Sample size (n=5).** Appropriate for formative usability testing (a five-user
  study surfaces the majority of usability problems) but not for precise quantitative
  generalisation; the medians are indicative, especially the per-command latencies
  (1–5 turns per command).
- **Derived task success.** Success here means the *intended command was eventually
  routed and answered*, taken from the routing log — a proxy for, not an independent
  observer's judgement of, whether the participant achieved the underlying goal. True
  task-completion rates may differ and would require separate moderator scoring.
- **Latency caveats.** The relay sleeps when idle, so the first turn of most sessions
  carried a cold-start penalty that inflates the wake→first-word figure; warm
  responsiveness (~5 s end-of-speech→first-word) is closer to, but still above, the
  ≤2.5 s design target. The wake→first-word figure (~12 s) additionally includes the
  time the participant spent speaking the command and the listening-activation window.
- **Transcription noise.** Speech-to-text occasionally garbled utterances, which
  contributed to some of the recoveries.
